Why repipe

Small tool, deliberate opinions.

Every behavior is on purpose: it retries nothing you didn't ask for, refuses to gamble with prod, and speaks whichever CI host your repo lives on.

{ }

Zero dependencies

One Python 3 standard-library script. No pip, no jq, no runtime to manage. Shipped as a single zipapp.

⇩

curl-installable

One line drops it on your PATH. repipe upgrade swaps itself for the latest build, atomically.

⇄

Provider-agnostic

Bitbucket Cloud and GitHub Actions ship today. The core never touches the network — new adapters are drop-in.

↻

Opt-in auto-retry

repipe retries nothing by default. You list the transient-error patterns worth re-triggering; no match, no retry.

≡

Design your own inputs

Per-repo variable schema — enum, default, required, pattern, autofill, remembered — validated locally in ~1s before any API call.

⚠

Production-safe

Prod pipelines need a typed-name confirm, never auto-retry unless forced, and a manual deploy gate reports HALTED with a deep link — never hangs.

▸

Interactive TUI

Arrow-key picker, live spinner, step counter, back-navigation — with a clean numbered fallback when there's no TTY.

✓

Scriptable

Flags for everything and honest exit codes, so CI can branch on success, no-match, exhausted, config, or timeout.

Quick start

Three steps to your first retry.

1

Install

Drops repipe into ~/.local/bin and checks for python3.

curl -fsSL https://raw.githubusercontent.com/AbhayG21/repipe/main/install.sh | bash
2

Authenticate

A token for your CI host, set as an env var — never written to a file.

# GitHub: a token with actions:write (or GITHUB_TOKEN in CI)
export REPIPE_TOKEN="<your-token>"
3

Run it

Interactive picks pipeline, branch and variables for you. Or go fully scriptable for CI.

# everyday: interactive — pick, trigger, watch, retry
repipe

# scriptable — trigger and auto-retry on your pattern
repipe run -p deploy-qa -b main \
  --retry-on "OutOfMemoryError" --max-retries 3 --yes

Configuration

Design your own pipeline inputs.

Constrain each variable in per-repo config; repipe drives its prompts and its ~1-second local validation from it. Nothing about your org is hardcoded.

# ~/.config/repipe/config.toml
[repos."your-org/your-repo".variables.Environment]
enum     = ["staging", "canary", "production"]
default  = "staging"
required = true

[repos."your-org/your-repo".variables.Owner]
pattern  = ".+@.+"
autofill = "git_email"   # fill & skip the prompt

Auto-retry, on your terms

List patterns in retry_on or pass --retry-on. On failure, repipe reads the failed step's log and re-triggers only on a match — otherwise it stops and surfaces the failure. It never loops.

repipe suggestions  # starter transient errors
0 success / halted-at-gate
1 failed — no match
2 retries exhausted
3 config / auth
4 timeout
